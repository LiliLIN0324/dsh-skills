# 产品介绍卡片（编号 JPG 系列）

把内容做成一套横版图，一张一个论点，编号 `01.jpg…NN.jpg`。画幅固定 4762×2678，可直接进 `fig/<slug>/` 或站内作品详情。

## 固定规格（不要改）

| 项 | 值 |
|---|---|
| 像素 | **4762 × 2678**（16:9，已验证 riffle / xihu-panorama 全部同尺寸） |
| 格式 | JPG，q≈88–92，单张目标 0.5–4 MB |
| 命名 | `01.jpg`、`02.jpg`……补零两位；不混入 `logo.jpg` |
| 目录 | `fig/<slug>/`；封面 logo 单独 `logo.jpg` |
| 数量 | 商业介绍 10–20 张，默认 14 张 |

4762×2678 = CSS **2381×1339** @ DPR 2。按这个视口做页面再截图，才能不缩放、不出锯齿。

## 硬规则：图文结合（最重要）

**只堆文字的卡片等于没做。** 每页必须有一张真实界面图，图占版面 ≥ 40%，文字最多三条。

- 禁止连续两页纯文字；只有「边界/声明」页允许文字为主，但也要配一张产品图。
- 图片必须是**目标项目的真实截图**，不是示意图、不是库存图、不是 AI 生图。
- 封面用品牌页/主界面，收尾用产品主视觉，不用纯字封面。

### 素材来源顺序

1. 目标项目的在线 demo / 官网（首选）：真实流程截图。
2. 仓库 `docs/images`、README 里的产品截图与结果图。
3. 都没有时，才退到产品图 + 数据图拼版。

### 取材流程（先抓素材，再写文案）

1. 打开项目官网/仓库，把产品的**核心操作流程**每一步截一遍（输入 → 处理 → 输出），2381×1339、DPR 1 即可（材料图，最终会缩放裁切）。具体步骤按产品实际功能定，不套用固定步骤名。
2. 落在 `_work/imgs/`，命名 `flow-1.jpg…flow-N.jpg`；仓库图另存 `ui-*.png`、`art-*.png`。
3. 只有素材齐了才动笔写卡片，文案围绕**图上真实可见的东西**写，不写图上没有的功能。

### 抓不到图的常见坑

- ModelScope / 在线 demo 是 iframe 包裹：先 `page.frames()` 找到 URL 含项目域名的那个 frame 再操作，直接访问子路由会白屏。
- 登录页若演示账号公开（如页面写「测试账号 xxx / 密码 xxx」），可直接登录抓全流程；凭证只用于截图，不写进交付物。
- 截图出现「演示」水印时保留原样，不 P 掉（会失真），靠裁切避开水印密集区。

## 版式类型（只用这四种）

| 型 | 结构 | 用途 |
|---|---|---|
| A 封面 | 左文 46% + 右图 54% 满高裁切 | 封面、收尾 |
| B 满幅 | 整幅界面图 + 底部压字条 | 流程总览、平台清单 |
| C 分栏 | 文 780px + 图其余（左文右图/左图右文交替） | 单点说明页 |
| D 并置 | 两张同高图并排 + 一行说明 | 对比、两种输出 |

图一律 `object-fit: cover`，不拉伸；只用极轻投影，不描粗边、不套大圆角卡片。

## 截图呈现（必做）

真实界面要**包进系统窗口**，不要裸贴：

- macOS 窗口：圆角 18、浅灰标题栏 56px、左侧红黄绿三点（`#FF5F57`/`#FEBC2E`/`#28C840`）、标题居中灰色 17px；浏览器页把标题换成白底地址条。
- Windows 窗口：标题栏左侧品牌色小方块 + 应用名，右侧 `– □ ✕`。
- 窗口内截图 `object-fit: cover`，裁上部；整册至少 4–5 页用窗口，其余可出血贴边，形成节奏。
- 封面**禁用登录页、空白表单、报错页**。封面要「产品正在工作」的画面（选品、成稿、平台页），优先给窗口边框 + 完整留边，而不是糊一层遮罩。

## 视觉系统（避免「土」）

配色必须从**目标产品自身**取，先看它的主界面截图，再定色板：

- 底色：近白 `#FFFFFF` + 一层极淡品牌色氛围光（radial 4–18% 透明度）。**禁用暖米色/象牙黄纸底**，那是模板味最重的来源。
- 主色：产品 UI 里的强调色（如玫红 `#D42B5C`），只用于标签、数字、方点，一页最多两处。
- 字色：`#15151A` 主 / `#3A3A44` 次 / `#86868F` 注释。
- 投影只用两层极淡：`0 1px 2px rgba(21,21,26,.05)` + `0 18px 44px rgba(21,21,26,.07)`，配 1px `rgba(21,21,26,.09)` 描边。**禁用 `0 38px 80px`、透明度 >10% 的大灰影**——白底上会显脏，是「土」的第二大来源。

版式规则：

- **不要把字摆在四个角。** 只留右下页码 `03 / 12`，其余角一律空着；栏目标签放标题上方，不放到页眉右上。
- 边距：左右 150 px、上下 120 px；图片可以出血到边，文字永不出血。
- 字号阶梯只用四级：标题 168/96 / 小标 54 / 正文 32 / 注释 22。
- 大标题用衬线体（Noto Serif SC 900），正文用无衬线（Noto Sans SC 300/500）。
- 标题栏宽小于 900 px 时，标题降到 76 px，宁可两行也不出孤字断行。
- 表格不要框线，只用 1px 浅分隔线（`#EEECF1`）。
- 不放 emoji、图标、色块拼贴、多层渐变。

## 出血与遮罩

- 全出血截图 + 白渐变遮罩压字时，遮罩靠字一侧必须接近纯白（`#FFF` 到 38%，之后才衰减），否则底图里的原文字会透出来，显脏。
- 截图不描边、不用大投影，只给一层极轻 `0 32px 80px rgba(21,21,26,.10)`；分栏页让图出血到画布边缘。

## 叙事骨架（通用占位，按产品实际功能填）

骨架只定**页型顺序**，不写死具体步骤名和数字。每页内容从目标产品的真实功能和截图里取，数字必须与截图一致，不编造。

1. **封面**：产品名 + 一句话定位 + 主界面/品牌页截图
2. **问题**：这件事难在哪（配现状痛点图或最糟结果图）
3. **方案总览**：满幅产品页 + 核心流程条（输入 → 处理 → 输出）
4–N. **核心能力页**：按产品实际功能拆，每页一件事。一个功能一页，放不下就拆页，不缩字号。数量随产品复杂度定（通常 4–8 页）。
- 若产品有明显的分步操作流程，按步骤顺序排；若产品是多个并列模块，按重要性排。
- 每页截图 + 最多三条要点，数字从截图里取。
N+1. **结果/输出**：最终产物截图 + 关键数据（字数/数量/指标等，必须真实）
N+2. **技术/规格**：品牌图 + 事实表（形态、数据、启动方式、边界）
N+3. **边界**：产品图 + 不承诺什么（2–4 条）
末页 **收尾**：体验入口 + 仓库 + 主视觉

> 示例（仅供理解结构，不套用内容）：AI 软文工具的核心能力页是「选品→选客户→选平台→追问→出稿→回查→改稿」；地图工具的核心能力页可能是「底图→标注→协作→导出」。

每页只讲一件事，放不下就拆页，不缩字号。
